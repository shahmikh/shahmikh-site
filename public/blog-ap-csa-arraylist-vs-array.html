AP CSA ArrayList vs Array: When to Use Each and How to Write Free-Response Question 3

By Syed Shahmikh Ali · Published 2026-11-12 · Updated 2026-11-12

Use an array when the number of elements is fixed, and an ArrayList when you need to add or remove elements. On the AP Computer Science A exam this matters most in free-response Question 3, where you write one method that analyses and often changes an ArrayList, and where the classic mistake is skipping an element after a removal.

Key takeaways

  • An array has a fixed length that cannot be changed. An ArrayList is mutable in size, so it is the right choice whenever elements are added or removed.
  • The Java Quick Reference gives you six ArrayList methods: size, two versions of add, get, set and remove. Learn exactly what each one returns.
  • Free-response Question 3 is Data Analysis with ArrayList: you write one method that uses, analyses and changes the data in an ArrayList of objects.
  • Removing while moving forward through a list shifts later elements left, so a plain for loop skips the element after each removal. Loop backwards, or only move on when nothing was removed.
  • Never add or remove inside an enhanced for loop, because it can cause a ConcurrentModificationException.

When should you use an array and when an ArrayList?

Use an array when you know the size up front and it will not change, and an ArrayList when the collection grows or shrinks. The course and exam description says an ArrayList is "mutable in size" and holds object references, while an array's length cannot be changed once it is created.

Here is the decision I give students, in the order I ask the questions:

QuestionIf yes
Will elements be added or removed?ArrayList
Do you need to store plain int or double values with no extra work?Array (an ArrayList stores wrapper objects such as Integer, with autoboxing doing the conversion)
Is the data a grid of rows and columns?2D array
Does the question hand you one of them?Use the type you are given, and do not convert it

On the exam the choice is usually made for you, because the question states the type. The skill being tested is using that type correctly, so the decision table matters most when you write your own practice programs.

Which ArrayList methods do you need to know?

Six, and they are all in the Java Quick Reference, which the exam page says is built into the Bluebook app. The course and exam description lists them under Topic 4.8:

MethodWhat it does
int size()Returns the number of elements
boolean add(E obj)Appends to the end and returns true
void add(int index, E obj)Inserts at the index, shifting later elements right
E get(int index)Returns the element at the index
E set(int index, E obj)Replaces the element and returns the old one
E remove(int index)Removes the element, shifting later elements left, and returns it

Valid indexes run from 0 to size() - 1, and an index outside that range throws an IndexOutOfBoundsException. Two details cost marks. First, an array uses length with no brackets and an ArrayList uses size() with brackets, so mixing them up fails to compile. Second, the "shifting" in add and remove is the reason loops go wrong, which is the next section.

What does free-response Question 3 ask for?

You write one method that uses, analyses and changes data stored in an ArrayList. The exam page lists Question 3 as "Data Analysis with ArrayList", and the course description says you get an outline of a data set represented by a class and write one method from given specifications and examples.

The same description notes that solutions often insert or remove elements, so you have to adjust loop counters to avoid skipping an element or accessing one that no longer exists. That one sentence is the whole difficulty of the question. The method itself is usually short. Whether it works depends on how you handle the indexes after a removal.

Why does removing elements in a loop skip items?

Because remove shifts every later element one place left, so the element that was next is now at the index you just looked at, and your loop counter moves past it. Here is a method I wrote and ran to show it. It should remove every word shorter than minLength and return how many it removed:

public static int removeShort(ArrayList<String> words, int minLength)
{
    int removed = 0;
    for (int i = 0; i < words.size(); i++)
    {
        if (words.get(i).length() < minLength)
        {
            words.remove(i);
            removed++;
        }
    }
    return removed;
}

I called it with the list [hi, to, tree, a, cat] and minLength 3. It returned 2 and left [to, tree, cat]. The word "hi" was removed, "to" slid into index 0, and the loop moved on to index 1 without ever checking it. The word "a" was removed correctly because it did not follow another removal. The correct result is [tree, cat] and a return value of 3.

This is an example I created, not a College Board question. The pattern is the point: any time a loop removes and a neighbour might also need removing, a forward for loop is a bug.

What are the two safe ways to remove while looping?

Loop backwards, or only move forward when you did not remove anything. Both give the correct answer on the same test list. I ran each and got a return value of 3 and the list [tree, cat].

The backwards loop is the one I recommend under exam pressure, because it has no extra logic to get wrong:

for (int i = words.size() - 1; i >= 0; i--)
{
    if (words.get(i).length() < minLength)
    {
        words.remove(i);
        removed++;
    }
}

Removing at index i only shifts elements after i, and a backwards loop has already dealt with those. The second option is a while loop where the counter only increases in the else branch:

int i = 0;
while (i < words.size())
{
    if (words.get(i).length() < minLength)
    {
        words.remove(i);
        removed++;
    }
    else
    {
        i++;
    }
}

You can also write i-- after a removal inside a for loop, which does the same job but is easier to forget. Pick one pattern and use it every time, so you do not have to think about it on exam day.

Can you remove inside an enhanced for loop?

No. The course description says that changing the size of the list during an enhanced for traversal can cause a ConcurrentModificationException, so elements should not be added or removed in that loop. Use an enhanced for loop when you only read values, and a standard for loop with an index when you add, remove or set elements.

How should you practise Question 3?

Write each method on paper, then type it into an IDE and test it on a list where two neighbours both need removing. Paper first, because the exam is a written method, and the test case second, because that is the case that exposes the skipping bug.

  1. Write the method on paper in about 15 minutes, with the loop skeleton first.
  2. Before you type it, predict the output for a list with two adjacent elements that both match.
  3. Run it and compare. If it differs, find the exact index where the loop went wrong.
  4. Rewrite it using the backwards loop and confirm the output.
  5. Change the task: count instead of remove, then replace with set, then insert with add(index, obj).

Do this with a different task each time for two weeks and the pattern becomes automatic. If you want someone to read your handwritten answers and point at the line that breaks, that is what I do in AP CSA tutoring, and you can book a free call to talk through a plan.

Frequently asked questions

Can I use an array instead of an ArrayList in Question 3?

The question gives you an ArrayList and asks you to write a method using the data in it. Work with the type you are given. Converting to an array adds extra code and extra chances to make a mistake.

What is the difference between size() and length?

An ArrayList uses the method size(), with brackets. An array uses length with no brackets. Writing the wrong one will not compile, so check which type you are holding before you write the loop condition.

Is a backwards loop always better when removing?

For removing, it is the simplest safe choice because removal only shifts elements you have already processed. If the order of results matters, such as building a new list in the original order, a forward loop with careful counter handling may be clearer.
