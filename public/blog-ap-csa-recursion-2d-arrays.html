AP CSA Recursion and 2D Arrays: Where Students Lose Marks and How to Fix It

By Syed Shahmikh Ali · Published 2026-11-09 · Updated 2026-11-09

On the AP Computer Science A exam, recursion is assessed only in the multiple-choice section, so you need to trace recursive code, not write it. 2D arrays are the opposite: they are the subject of free-response Question 4, where you have to write a method from scratch. Prepare for each in the way it is actually tested and you will stop spending time on the wrong skill.

Key takeaways

  • College Board's course description says recursion is assessed only through multiple-choice questions, which usually ask for the result or behavior of a recursive call.
  • Free-response Question 4 is a 2D array question: write one method that uses, analyzes and manipulates data in a 2D array.
  • For recursion, practice writing out the calls on paper until you can trace them without guessing.
  • For 2D arrays, the two most common slips are mixing up rows and columns and using the wrong length in the inner loop.
  • Unit 4, Data Collections, is listed at 30% to 40% of the multiple-choice section, so this material is worth the time.

Where do recursion and 2D arrays appear on the exam?

Recursion appears only in the multiple-choice section, and 2D arrays appear in both sections. The exam is digital and has two parts, according to the AP Computer Science A exam page: Section I is 42 multiple-choice questions in 1 hour 30 minutes, worth 55% of the score, and Section II is 4 free-response questions in 1 hour 30 minutes, worth 45%.

The four free-response questions are Methods and Control Structures, Class Design, Data Analysis with ArrayList, and 2D Array. Both topics here belong to Unit 4, Data Collections, which the course and exam description lists at 30% to 40% of the multiple-choice section. In that document, 2D arrays are topics 4.11 to 4.13 and recursion is topics 4.16 and 4.17. Check the current version of the document for your exam year, since I only read the version available this week.

How is recursion tested?

It is tested by asking what a recursive method does. The course description states that "Recursion is assessed only through the multiple-choice section of the exam" and adds that students are often asked to determine the result of a specific recursive call or to describe what a recursive method does.

That changes how you should study it. You will not lose free-response marks because you could not write a recursive method, but you can lose several multiple-choice marks if you guess at traces. It also means that slow, careful tracing on paper is worth more than memorising famous recursive examples. The same document suggests drawing a call tree or a stack trace to count how many times a recursive method runs, which is a good habit to copy.

How do you trace a recursive method without guessing?

Write every call on its own line, wait to fill in the return values, and work back up once you hit the base case. Here is a small example I wrote and ran to check the answers:

public static int mystery(int n)
{
    if (n <= 1)
        return 1;
    return n + mystery(n - 2);
}

What does mystery(5) return? Go down first, then come back up:

  1. mystery(5) needs 5 + mystery(3).
  2. mystery(3) needs 3 + mystery(1).
  3. mystery(1) hits the base case and returns 1.
  4. Back up: mystery(3) is 3 + 1 = 4, then mystery(5) is 5 + 4 = 9.

Now try mystery(4). The chain is 4, 2, 0, and 0 is below 2, so the base case returns 1 and the answer is 4 + 2 + 1 = 7. Many students assume the chain always ends at exactly 1, so this one is a useful trap to practise. Check what the base case actually allows before you start.

The checklist I teach is short. Find the base case first. Check that each call moves toward it. Then write the calls down, not in your head. If a method makes two recursive calls, draw it as a tree, since the count of calls grows quickly.

What are the usual recursion mistakes?

The usual mistakes are trying to hold the whole chain in your head, ignoring the order of the work, and misreading the base case. A few specifics:

  • Printing before or after the call. If a method prints, then calls itself, the output order is different from calling itself first and then printing. Mark which line comes before the recursive call and which after.
  • Dropping the work done on the way back. In n + mystery(n - 2), the n + is still waiting after each call returns. Students often stop once they reach the base case and forget the additions.
  • Forgetting integer division. A method that uses n / 10 or n % 10 to peel digits off a number depends on integer division. For example, a digit-sum method on 472 gives 2 + 7 + 4 = 13.

    • Practise with a mix of questions, then repeat them a few days later with the notes closed. My post on using past papers for computer science revision has a method that fits well here.

    What does the 2D array free-response question ask for?

    It asks you to write one method that uses, analyzes and manipulates data in a 2D array. That wording comes from College Board's description of Question 4, and it shows what the question is about: loops over rows and columns, plus the logic that decides what to do with each value.

    The course description lists the skills behind it. Topic 4.11 states that the first index is for rows and the second is for columns. Topic 4.12 defines row-major order as traversal across each row, and notes that the outer loop of a nested enhanced for loop traverses the rows. Topic 4.13 is about writing standard and original algorithms for a context or specification that involves 2D arrays. All of that is in the course and exam description.

    How do you write a 2D array method that works first time?

    Write the loop skeleton first, with the row count and the column count correct, then add the logic inside it. Here is a method I wrote and tested that returns the sum of each column:

    public static int[] columnSums(int[][] grid)
{
    int[] sums = new int[grid[0].length];
    for (int r = 0; r < grid.length; r++)
    {
        for (int c = 0; c < grid[r].length; c++)
        {
            sums[c] += grid[r][c];
        }
    }
    return sums;
}

    Called on {{1, 2, 3}, {4, 5, 6}}, it returns [5, 7, 9]. Notice three things. grid.length is the number of rows. grid[r].length is the number of columns in row r. And the result array is sized by the number of columns, because there is one sum per column.

    When you practise, say the dimensions out loud before writing a loop: "rows go down, columns go across, the first index is the row." It sounds silly, but it prevents the most common slip.

    What are the usual 2D array mistakes?

    Most lost marks come from swapped indexes, wrong bounds and sloppy handling of the result. Look for these on every practice answer:

    • Swapped indexes. Writing grid[c][r] when you meant grid[r][c]. On a square grid it may even seem to work, which hides the bug.
    • Wrong inner bound. Using grid.length where you need grid[r].length, so a rectangular array throws an ArrayIndexOutOfBoundsException.
    • Changing a value while reading it. If a method must compare neighbors, decide whether you are reading the old values or the new ones.
    • Going out of bounds on neighbors. Checking grid[r - 1][c] on row 0 will fail unless you test the edge first.
    • Not returning or updating what the question asks for. Reread the method header and the sentence that says what it must return.

    Check your answer against the official scoring guidelines for past questions, and write a loop that visits every row and column even when you cannot finish the logic inside it.

    What is a good two-week plan for these topics?

    Split the time by how each topic is tested: tracing practice for recursion, writing practice for 2D arrays. This is the plan I would give a student who has met both topics but feels shaky. It is a suggestion from my teaching, not an official schedule.

    1. Days 1 to 3. Trace five recursive methods on paper, including one with a base case that is not 1 and one that prints.
    2. Days 4 to 5. Write the recursive version of a loop you already know, such as a sum of digits, then compare with the loop. This builds understanding even though writing recursion is not tested.
    3. Days 6 to 9. Write four 2D array methods by hand with no IDE: a row sum, a column sum, a count of values that meet a condition, and a method that finds the largest value.
    4. Days 10 to 12. Do a past 2D array free-response question under a time limit, then mark it against the official scoring guidelines.
    5. Days 13 to 14. Redo the traces and one array method with the notes closed.

    Frequently asked questions

    Do I need to write recursive methods on the AP CSA free response?

    According to the course description, recursion is assessed only through the multiple-choice section. You still need to read and trace recursive code, and writing a few recursive methods in practice helps you do that.

    Should I use enhanced for loops or standard for loops for 2D arrays?

    Either works for reading values. Use a standard nested for loop when you need the row and column indexes or when you must change elements, and an enhanced loop when you only need the values.

    How many 2D array questions are on the exam?

    There is one 2D array free-response question, Question 4. 2D arrays can also appear in the multiple-choice section as part of Unit 4, so practise both formats.
