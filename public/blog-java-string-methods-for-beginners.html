Java String Methods Every Beginner Should Know, With Output You Can Check

By Syed Shahmikh Ali · Published 2026-11-19 · Updated 2026-11-19

Learn length, substring, indexOf, equals, compareTo and split first, plus charAt for single characters. They cover most String tasks in beginner Java, and the first six are the ones on the College Board's AP CSA Java Quick Reference.

Key takeaways

  • Indexes start at 0. The last valid index is length() - 1, but substring(from, to) allows to up to length() and excludes the character at to.
  • indexOf returns -1 when the text is not found, so a result of 0 or more means it was found.
  • Compare Strings with equals, not ==. The == operator checks whether two variables refer to the same object.
  • Strings cannot be changed. Methods such as toUpperCase and trim return a new String, so assign the result or it is lost.
  • Predict the output of each small program by hand before running it, and test an empty String and a one-character String.

Which Java String methods should a beginner learn first?

Learn eight: length, substring (both forms), indexOf, equals, compareTo and split, plus charAt for single characters. The first six are exactly the String methods on the College Board AP Computer Science A Java Quick Reference, the sheet students get during the exam, so they are worth knowing cold even if you never take AP.

The quick reference I read lists the String constructor, length(), substring(int from, int to), substring(int from), indexOf(String), equals(Object), compareTo(String) and split(String). It does not list charAt, which is why many AP courses use substring(i, i + 1) to pull out one character. Both work in real Java. Everything below follows the official Java SE 17 String documentation, and every output shown comes from a program I compiled and ran on Java 21.

How do indexes and substring work?

Positions start at 0, and substring(from, to) includes from but stops before to. The Oracle docs put it this way: the substring "begins at the specified beginIndex and extends to the character at index endIndex - 1," so its length is endIndex - beginIndex.

String s = "computer science";
s.length();         // 16
s.substring(0, 8);  // "computer"
s.substring(9);     // "science"
s.charAt(0);        // 'c'

A quick habit that prevents most off-by-one mistakes: the last valid index is length() - 1, but the largest valid end for substring is length(). That asymmetry trips up almost everyone once. If you go past it, Java throws IndexOutOfBoundsException. Running s.substring(5, 20) printed Range [5, 20) out of bounds for length 16, and s.charAt(16) printed Index 16 out of bounds for length 16. Wording can differ between Java versions. If you want a deeper look at reading those messages, see Debugging Java for beginners.

What does indexOf return when it finds nothing?

It returns -1. Per the documentation, indexOf(String) returns "the index of the first occurrence of the specified substring, or -1 if there is no such occurrence." That makes it both a search tool and a yes/no test.

s.indexOf("science");  // 9
s.indexOf("python");   // -1

A useful trick is counting vowels by checking each letter against a vowel string. The call "aeiou".indexOf(letter) >= 0 asks whether the letter appears in the vowel list:

int count = 0;
for (int i = 0; i < s.length(); i++) {
    if ("aeiou".indexOf(s.substring(i, i + 1)) >= 0) count++;
}
// count is 6 for "computer science"

Check the loop condition: i < s.length(), not <=. Using <= would run one step too far and throw the exception above.

Why does == fail for comparing Strings?

Because == asks whether two variables point to the same object, not whether the text matches. Use equals. The documentation says the result is true "if and only if the argument is not null and is a String object that represents the same sequence of characters as this object."

String a = new String("java");
String b = new String("java");
a == b;          // false
a.equals(b);     // true
"Java".equals("java");            // false
"Java".equalsIgnoreCase("java");  // true

For ordering, compareTo returns a negative number, zero or a positive number. In my test "apple".compareTo("banana") < 0 was true. The docs say it returns 0 exactly when equals would return true, and the comparison is based on Unicode values, so an uppercase letter sorts before a lowercase one. Do not rely on the exact size of the number, only on its sign.

Why does toUpperCase seem to do nothing?

Strings cannot be changed after they are created, so methods return a new String instead of editing the old one. The class documentation states it plainly: "Strings are constant; their values cannot be changed after they are created."

String t = "hello";
t.toUpperCase();
System.out.println(t);   // hello  (result thrown away)
t = t.toUpperCase();
System.out.println(t);   // HELLO

The first call produced "HELLO" and nothing kept it. This is one of the most common beginner bugs, and Java gives no error for it. The fix is to assign the result. The same rule applies to trim and replace. For example "a--b".replace("-", "+") gives a++b and leaves the original untouched.

How do you split a String into pieces?

Use split with the separator and you get an array. The documentation describes it as splitting "around matches of the given regular expression," and it says trailing empty strings are not included in the result.

String[] parts = "3,5,8".split(",");
parts.length;   // 3
parts[1];       // "5"

The text you pass is a regular expression, which matters for characters such as the dot or the pipe. A comma or a space is safe. For anything else, check the documentation before trusting it. If you pull numbers out this way, remember each piece is still text. Reading data into an array is a natural next step, and ArrayList versus array covers how to store it.

What is a good way to practise these methods?

Write small programs that predict the output first, then run them. Here are four that use only the methods above, and I would do them in this order:

  1. Print a String backwards. My version loops from length() - 1 down to 0 and joins substring(i, i + 1). It turned "stressed" into "desserts".
  2. Count how many times one letter appears.
  3. Check whether a word is a palindrome using equals, never ==.
  4. Split a line like "3,5,8", convert each piece and add them up.

For each one, write down what you expect for an empty String and for a one-character String before you run it. Those two cases catch most index mistakes. Frequently asked questions

Is charAt on the AP CSA exam?

The Java Quick Reference I read does not list charAt, and it does list substring, indexOf, length, equals, compareTo and split. Many courses teach substring(i, i + 1) for single characters for that reason. Check the current Course and Exam Description for your year, since the sheet is updated by College Board.

What is the difference between trim and strip?

According to the Java SE 17 documentation, trim removes leading and trailing characters with a code point of U+0020 or below, while strip, added in Java 11, removes white space as Java defines it. For everyday text the results are usually the same.

Why does my split code give an extra empty String at the start?

If the text begins with the separator, the first piece is an empty String. Only trailing empty strings are removed by default, as the documentation says. Trim or skip the leading separator before splitting.
