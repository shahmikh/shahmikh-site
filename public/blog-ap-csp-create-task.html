AP CSP Create Task: How the Written Responses Are Scored and How to Build for Them

By Syed Shahmikh Ali · Published 2026-10-29 · Updated 2026-10-29

The AP CSP Create performance task is 30% of your AP score, and it has two parts: a program, video and Personalized Project Reference (PPR) you build in class, and four written responses you answer on exam day about your own code. The written responses are scored one point per prompt, and the College Board's own reports show the same handful of mistakes costing points year after year. The practical fix is to design your program backwards from those four prompts, so that the code you write gives you something clear to say.

Key takeaways

  • The Create task is 30% of the AP CSP score. The other 70% is the 70-question multiple-choice exam.
  • You get at least 9 hours of in-class time to build the program, the video and the PPR, and all three are submitted through the AP Digital Portfolio.
  • The written responses happen at the end of the course: 2 questions, 60 minutes, 4 prompts, and you may use your PPR while you answer.
  • In the 2025 scoring guidelines each of the four prompts is worth 1 point, so one vague answer is a real loss.
  • The most common errors are naming the wrong thing (the whole if statement instead of its Boolean expression, a syntax error instead of a logic error) rather than not knowing the material.

What exactly is the Create performance task?

It is the second section of the exam, worth 30% of your score, and it has a through-course part and an end-of-course part. According to the College Board's AP CSP assessment page, you develop a program of your choice plus a video and a Personalized Project Reference, using 9 hours of in-class time, and submit all three through the AP Digital Portfolio. The 2026-27 final deadline on that page is Friday 30 April 2027, 11:59 PM ET.

The end-of-course part is 2 questions in 60 minutes, covering 4 prompts. The College Board's note on the 2023-24 changes explains that the PPR holds screen captures of your list and your procedure, and that the written responses moved to the exam so you answer them about that PPR. Components that are not submitted as final are not scored, so submit early.

PromptTopicWhat it asks you to do
1Program design, function and purposeGive an example output and explain what it shows about your program
2(a)Algorithm developmentName the Boolean expression in the first selection statement, give values that make it true, and say why
2(b)Errors and testingDescribe a change to your procedure that causes a logic error, and what would go wrong
2(c)Data and procedural abstractionExplain what would change in the list-handling code if several items were added to the end of the list

How is each written response scored?

Each prompt is a single point: you either earn it or you do not. The 2025 scoring guidelines (Set 1) describe what earns the point and what does not, and the pattern is consistent. Your answer has to be about your own code, specific, accurate and consistent with how the program really works.

  • Prompt 1: identify at least one example output and explain how it shows something your program can do. The output cannot be a compiler error or other non-normal event.
  • Prompt 2(a): point to the Boolean expression in the first selection statement, give a specific value or set of values that makes it true, and explain why those values do. If the procedure has no selection statement, the point is not available.
  • Prompt 2(b): describe a change another programmer could make (add, change or delete code) that causes a logic error in your procedure, and say how the behaviour would change. Saying only that the program would not run does not earn the point.
  • Prompt 2(c): explain how the code that accesses or manipulates your list would need to change if several elements were added to the end, or explain why no change is needed. A trivial use of the list does not earn the point.

Which mistakes cost students points most often?

The College Board's 2025 Chief Reader report lists the errors graders saw. They are specific enough to avoid once you know them:

  • 2(a): naming the whole selection statement instead of its Boolean expression, giving a general category of values instead of specific ones, or choosing a later selection statement instead of the first.
  • 2(b): describing a syntax error (which stops the program running) instead of a logic error (which gives wrong or unexpected behaviour), or describing a change to code outside the list section.
  • 2(c): describing the whole program, explaining benefits to end users instead of benefits to the people maintaining the code, or confusing procedural abstraction with data abstraction.
  • Program and video: using an event handler in place of a procedure you wrote yourself, building a list that is never accessed, or showing a static screen in the video instead of the program running with input.

Almost none of these are knowledge gaps. They are precision gaps, which means practice with feedback fixes them quickly.

How should you design your program with the prompts in mind?

This part is my own teaching advice, not an official rule: choose a program idea that makes each prompt easy to answer, before you write any code. The College Board does not require a particular language or topic, so the idea is yours to pick. These choices are the ones I would make.

  1. Put a clear if statement first in your procedure. Prompt 2(a) is about the first selection statement, so make that one meaningful, with a condition like score > highScore or item is not already in the list. A condition that is always true makes the answer awkward.
  2. Give your procedure a parameter and a real job. Procedural abstraction is easier to explain when one procedure replaces several copies of the same code and takes a value that changes between calls.
  3. Use a list that the program really reads and changes. Loop over it with iteration. If you hard-code items[0], items[1] and items[2], the answer to 2(c) turns into a weak one.
  4. Know one safe way to break your procedure. For 2(b), a one-line example such as changing < to <= in a loop and explaining the wrong output is a clean logic error.
  5. Record your video with input visible. Show the program running and make clear where the input comes from, as the report advises.

How can you practise the written responses before exam day?

Write the four answers for your own program in advance, then ask someone to grade them with the official guideline in front of them. Students in my lessons do this on a paper copy of their PPR with the code visible and no notes, which is close to what exam day feels like.

A routine that works:

  1. Write all four answers in 20 minutes.
  2. Mark each against the scoring guideline wording, not against how it feels.
  3. For every lost point, rewrite the answer and note which error from the list above you made.
  4. Repeat with a classmate's program, so you practise on code you did not write.

The Chief Reader report suggests the same habit for teachers: write responses, critique each other's, and study low-scoring examples. If you want a second pair of eyes on yours, the AP CSP lessons page explains how my sessions work, or you can book a free call.

Frequently asked questions

Do I have to use a specific programming language for the Create task?

No. The College Board says AP CSP does not require a specific language. Use one that your teacher supports and that lets you write a procedure with a parameter, a list and a selection statement.

When do I submit the Create task?

The program, video and PPR are submitted through the AP Digital Portfolio, and the final deadline listed for the 2026-27 exam is 30 April 2027 at 11:59 PM ET. Anything not submitted as final is not scored, so ask your teacher for your school's earlier internal deadline.

Can I use my PPR when I answer the written responses?

Yes. The College Board says you can use your PPR while answering. That is why the code in it should be readable, with no comments or notes added, and why it needs to include your list and your procedure.
